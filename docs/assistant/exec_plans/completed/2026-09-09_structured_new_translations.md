## Evidence and design decisions

Canonical source inspection on 2026-09-09 established:

1. `pdf_text_order.py` retains body blocks only in `OrderedPageText`.
   `document_structure.structure_from_ordered()` expects `all_blocks`, so merely
   calling it currently produces uncertain text fallback, not full page geometry.
2. `OcrResult` and the selected Tesseract pass retain plain text, not its geometry.
   Bind geometry only to the actual winning extraction/OCR text. Never attach
   original PDF boxes to later crop-merged or image-grounded replacement text.
3. `openai_client.create_page_response()` has no schema/output bound or terminal
   structured status contract. Existing prompts/evaluation explicitly require a
   plain-text code block; appending JSON instructions would conflict with them.
4. Current workflow writes TXT before coordinator DONE. Resume checks TXT
   existence and settings, not a complete structured page unit or protocol/model/
   prompt/glossary-content identity. Independent atomic writes are insufficient.
5. The approved writer already rejects stale/mismatched sidecars and preserves
   TXT fallback. Its serializer is not a strict response validator: duplicate and
   extra IDs must be rejected before calling it.
6. Research `translation_structure.py` and `structured_artifacts.py` offer useful
   narrow primitives. Research `StructuredRun` imports unpromoted acceptance,
   recovery, OCR and cache policy and must not be transplanted wholesale.

Official OpenAI Structured Outputs guidance was searched and opened on 2026-09-09:
https://developers.openai.com/api/docs/guides/structured-outputs . It documents
Responses `text.format` JSON-schema output and separate refusal/incomplete handling.
Schema compliance is not legal/content completeness. Keep local coverage and
fidelity checks; actual model/account support is not proven by this docs check.
