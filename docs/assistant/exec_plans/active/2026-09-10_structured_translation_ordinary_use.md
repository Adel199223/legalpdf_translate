## Stage 1 evidence and assessment (PR #295 base, before Stage 2)

### What is already ready

PR #295 provides an opt-in structured path with source-owned block IDs, strict
response coverage, commit-last page bundles, recovery identity and source-aware
DOCX formatting. Saved structured runs can preserve their protocol identity, and
explicit protocol conflicts fail before dispatch. Existing runs without protocol
identity remain legacy. Formatting-only rebuild is intended to reuse saved
translation and extraction evidence without provider calls.

Those properties were verified on synthetic fixtures. They do not establish full
real-case legal fidelity, full-document layout, all-call cost, or suitability of
another model. Prior accepted real DOCX files were made through the earlier
formatting path and cannot be counted as structured-translation acceptance.

### Current selection behavior

`TranslationWorkflow` currently resolves the protocol from an explicit internal
argument, then inherited `LEGALPDF_TRANSLATION_PROTOCOL`, then the literal
`legacy_text_v1`. Browser, CLI, supported Qt and queue callers omit an explicit
protocol, so ordinary fresh work remains legacy. A future policy change can be
centralized without adding a public switch, but it must preserve saved-run
identity and the inherited-process legacy rollback.

The browser launcher can reuse an already-running server. Any future default or
rollback therefore takes effect only after an exact owned-process restart. Queue
checkpoints do not freeze protocol identity for untouched pending jobs. Activation
or rollback must start with no active or pending queue, or queue-schema evolution
must be separately designed. This plan chooses the smaller no-active-queue gate.

### Prerequisite P0 fixes

1. **Browser resume does not force resume semantics.**
   `TranslationJobManager.resume_job()` reuses the saved `RunConfig`, including a
   possible `resume=False` from Gmail-prepared jobs. Legacy workflow can clear
   intermediates and restart; structured workflow fails closed on occupied
   artifacts. Before activation, resume must clone the immutable config with
   `resume=True`. Real manager/workflow tests must prove that completed pages,
   usage and commit hashes survive and are not redispatched in both protocols.

2. **Workflow settings can escape an isolated browser workspace.**
   `TranslationService` reads its explicit `settings_path`, but
   `TranslationWorkflow.run()` independently calls global `load_gui_settings()`
   for glossaries, prompt addenda and timeouts. A shadow run can therefore consume
   live settings and alter request identity, cost or behavior. Add an internal
   injected settings snapshot or settings path; the browser service must pass its
   own path. CLI/Qt behavior remains compatible when the injection is omitted.

3. **Cost accounting and enforcement are not dispatch-complete.**
   The current cap is an optional, sampling-based per-run estimate whose default
   is no cap and warn. It is not a persistent reservation. Auth preflight, API OCR,
   retries, failed/refused/timed-out attempts and later review/correction can be
   unmetered. Structured reports deliberately say `not_evaluated_all_calls` and
   null the total. Current estimation can also add reasoning tokens to output
   tokens even though Responses output totals already include reasoning, causing
   double pricing. Cached input is observed but not fully priced.

   Before any paid acceptance, introduce one accounting/budget-context seam around
   every provider SDK dispatch: OCR, translation, explicit retry/correction and
   any model review. Accounting is always on. A conservative atomic reservation is
   mandatory before each call only when a hard budget context is injected (the
   acceptance ledger, or a product run configured with `BLOCK`). Product runs with
   the existing default no-cap/`WARN` policy retain that behavior while recording
   projected ceilings and actual/unknown cost. Use one unique call identity,
   prevent hidden transport retries, reconcile reported usage exactly once, and
   retain the full hold when usage is missing or outcome is uncertain. Missing
   legacy evidence is unknown, never zero. A run is cost-complete only when every
   dispatch is represented and the pricing snapshot is verified for the actual
   provider/model/date. Do not introduce a new global product cap.

4. **App bootstrap and provider cloning are not isolated enough for acceptance.**
   Constructing the browser app or reading bootstrap/capabilities can initialize
   power tools, translation, Gmail, Photos, Word/native and ambient credential
   state. Workflow worker cloning can rebuild clients and re-resolve ambient keys
   or SDK retry defaults. Add app-construction service injections and fail-closed
   tripwires so offline bootstrap/capability tests report `not_evaluated` without
   touching global/live/native state. Clone the configured SDK/key boundary. Set
   hidden SDK retries to zero and reproduce the existing retry eligibility,
   attempt ceiling, backoff, cancellation and timeout behavior as explicit
   workflow attempts; each attempt returns through the accounting seam. This
   changes attempt ownership, not the effective retry policy or maximum spend.

5. **The default flip has a large legacy-test migration surface.**
   More than one hundred tests instantiate `TranslationWorkflow` without a
   protocol; many use plaintext legacy fake clients. A constructor literal flip
   would reinterpret them and can produce false confidence. Pin tests that are
   intentionally legacy, while keeping dedicated unset-environment tests for the
   true browser/CLI/queue/Qt default path. Do not globally force legacy in a
   fixture that masks production selection.
