Use three separate measures of translation quality.

| Dimension | What the reviewer checks |
|---|---|
| Legal content | Meaning, parties and roles, conditions, dates, amounts, citations and protected literals against the original. A material omission, invention or changed obligation fails. |
| Structural fidelity | Headings introduce the correct body, labels own the correct values, tables preserve cells, columns read in order, signatures stay with their roles, and folios are legible exactly once. Read the actual Word pages. |
| Visual resemblance | Compare hierarchy, grouping, placement, relative spacing, rules, symbols and footer position. Record each visible difference, its impact and whether it matters for the case. Wrapping and pagination can change with language. |

Microsoft describes PDF content as positioned on a page, often without explicit paragraph or table relationships. PyMuPDF documents cases where extracted text order differs from the visual order. These constraints make an editable and recognizably similar translation a realistic target, while exact line and page matching is a poor universal acceptance rule. ## Where the architecture loses information

Ordinary browser Start goes through the translation job manager. The source stage reads PDF text or OCR and page images according to the saved policy. The workflow produces translated paragraphs, with semantic review on eligible runs. Automatic layout takes the selected wording, associates immutable paragraph IDs with source-page regions, and emits a separate editable DOCX that stays marked unreviewed. This protects wording and makes saved runs reproducible. A layout pass that receives already-merged paragraphs has limited ability to recover their original owners. The separate structured protocol already represents stable blocks, geometry, roles, cells and uncertainty. Switching the default to it would change which jobs receive ordinary automatic layout.

Source entry points include `TranslationJobManager.start_translate` in [translation_service.py](../../../src/legalpdf_translate/translation_service.py), [translation_policy.py](../../../src/legalpdf_translate/translation_policy.py), [ordinary_auto_layout_artifacts.py](../../../src/legalpdf_translate/ordinary_auto_layout_artifacts.py), [ordinary_auto_layout.py](../../../src/legalpdf_translate/ordinary_auto_layout.py), [saved_docx_layout_writer.py](../../../src/legalpdf_translate/saved_docx_layout_writer.py) and [document_structure.py](../../../src/legalpdf_translate/document_structure.py). Candidate-specific behavior was checked in the parity worktree identified in the handoff.

The browser, Gmail bridge, job database, accounting journal and historical resume contracts have different responsibilities. The observed legal, OCR, folio and reading-order failures occur inside the document pipeline. Replacing those adjacent systems would increase the preservation and integration work without addressing those failures. The campaign also found a genuine open-reader journal race. Fixing that bounded problem while preventing a duplicate paid call was worthwhile.

There is also maintenance debt in the layout policy. Candidate functions such as `_proposal_render_profile` enumerate successive saved policy fingerprints to decide which renderer features apply. Similar version checks recur as artifacts are read. That protects old jobs, but every new exception can require edits in several places. If this code is consolidated, first capture each existing fingerprint and replay a saved job per materially different behavior. A shared descriptor can then replace duplicate lists without changing what historical jobs rebuild. This is a secondary task after measuring the source error.

## A concrete experiment changed the diagnosis

A new fictional Portuguese form placed a heading, condition and deadline in each of two outlined panels. On both main and W10, flat extraction alternated between the panels. With staggered text and a full-width closing, it placed the closing before the right panel. A genuine ruled table showed the opposite danger of a global ordering change. Flat text read down its columns, but the existing structured representation recovered all six cell owners. A mocked ordinary Start sent both the interleaved text and the correct page image, then produced a DOCX with the order supplied by its scripted provider. This identifies an upstream ambiguity, not a demonstrated live mistranslation. [Reproduce the examples](PANEL_READING_ORDER.md)

The existing structure model also merged text from both panels across the gutter. An offline comparison using closed PDF rectangles and the original line boxes recovered both separate panels and the closing in the two positive fixtures. It recognized the ruled grid as a table and abstained on the overlapping, touching and borderless controls. That makes a **narrow extension before the merge** worth testing. It does not establish that all boxes are panels or that geometry alone determines reading order.

We then froze the diagnostic and had an independent reviewer label two previously unseen fictional pages. It recovered five of five heading-to-instruction links on a three-panel task sheet, whose ordinary text order was already correct. On an assignment register, it grouped the outlined columns confidently and recovered **zero of three task-to-owner relationships across the rows**. The boxes were in the right place. The mistake was interpreting “in the same box” as “belongs together.” Keep geometry advisory until the heading, row and visual evidence support the same relationship. This result argues against shipping the diagnostic rule. [Fixture details](PANEL_READING_ORDER.md)

## Which change earns its way into the app

1. Keep W10 available as the release candidate. In shadow, carry source region and cell ownership alongside the ordinary translation input where it is unambiguous. Reuse the existing block IDs and uncertainty fields where they fit. Preserve the current image input, wording checks, saved recipes and fallback.
2. Use these synthetic examples as development fixtures. Before tuning the shadow approach further, reserve unseen examples from distinct families, including side-by-side notices, a true table, a scanned or ambiguous layout, and a closing/signature case. Freeze independent human labels for each heading/body, cell/value and closing relationship. Keep these cases separate from the three already used for repairs. Use fictional or appropriately held private evidence.
3. Compare baseline and candidate on the same inputs. First score observed source relationships and preservations offline. Then compare ordinary Start and actual Word output on representative cases when the relevant scope allows. Show per-family counts of right, wrong and unproven relationships, material content errors, and extra manual corrections. Keep native appearance differences visible. Adopt only if an unseen failing family improves, material content errors stay at zero, and the correct controls retain their behavior. If that fails, keep ordinary behavior and identify the next broken boundary before another repair or paid trial.
4. For this release, keep the three-original requirement and one *successful* required Full on the final candidate. Plan expensive checks for a stable build. Earlier native successes and retained replays remain visible throughout development. They do not earn fresh acceptance on a new build. Representative holdouts and independently reviewed output are more informative about future documents than another attempt on a case used for tuning. [OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)

If held-out documents still lose relationships, trace the first divergence on the same frozen input. Correct source ownership followed by a wrong translated association points to translation alignment. Correct associations followed by a broken rendered page point to layout or the Word writer. If an experiment changes neither the observed failure nor the native result, end that line of work and revisit the responsible stage before spending again. This gives the project a reason to restructure a particular component, should the evidence warrant it.

**Keep Decisions outside production acceptance.** The endpoint provides typed predicates, choices and scores. In the project's preregistered screen it caught the detached signing group but missed the material footer-order error. Both repaired controls avoided alarms. That is one of two known defects detected on four correlated artifacts from one original. Nine calls cost about half a US cent. Low cost cannot compensate for the missed defect. Reconsider only as advisory review prioritization if it adds measurable value on unseen documents compared with the existing checks.
